React Refresher — ключові теми (пріоритет 1)

🔁 Rendering & Reconciliation
Знай різницю між re-render і re-mount. Коли React пропускає рендер? Що таке fiber? Як працює key prop при списках? Коли React.memo дійсно допомагає, а коли — ні?
// Це ре-рендер КОЖЕН раз — навіть якщо value не змінилась const handler = () => doSomething(); // new ref on every render // Фікс: const handler = useCallback(() => doSomething(), []); // React.memo корисний тільки якщо props стабільні за посиланням const Comp = React.memo(({ onClick }) => <button onClick={onClick} />);
🪝 Hooks — глибше ніж базово
useLayoutEffect vs useEffect — коли і чому. useRef для mutable values без re-render. useDeferredValue / useTransition для concurrent features. Custom hooks — як тестувати.
📦 State Management
Context — де підходить, де стає проблемою (re-render всього дерева). Zustand vs Redux Toolkit — трейд-офи. Як би ти спроектував стейт для сторінки інвойсів з фільтрами, пагінацією і real-time оновленнями?
🧪 Тестування React-компонентів
Testing Library: getByRole vs getByTestId — і чому перший кращий. Як мокати модулі, API. Що таке "тест, що не дає false confidence". fireEvent vs userEvent.

Архітектура — твоя перевага з Angular

DDD у фронтенді
  • Bounded contexts → feature modules
  • Domain layer без React-залежностей
  • Use cases / application services
  • Аналогія: те, що ти робив в Nx monorepo!
Clean Architecture
  • Dependency inversion у UI-коді
  • Adapters для API (не fetch напряму в компоненті)
  • Testability через інтерфейси
  • Інваріанти бізнес-логіки — не в компонентах
Design System
  • Compound components pattern
  • Headless UI підхід
  • Design tokens через CSS variables
  • Storybook як документація
// Feature-Sliced Design — знайома тобі як Nx domain libs src/ features/ invoices/ api/ ← adapters (HTTP → domain models) model/ ← стейт, бізнес-логіка, чиста TS ui/ ← React компоненти shared/ ui/ ← design system компоненти lib/ ← утиліти без фреймворкових залежностей

Типові питання на співбесіді — і як відповідати

«Розкажи про складний технічний challenge, який ти вирішував»
Формат STAR (Situation → Task → Action → Result). Готуй 2 приклади: один про архітектуру (як Nx monorepo або touch events directive), один про performance або складний UI. Числа завжди сильніше: "скоротили bundle на 30%", "TTI впав з 4s до 1.2s".
«Як ти підходиш до проектування фічі?»
1) Зрозуміти проблему → 2) API design (компонент/хук) → 3) edge cases → 4) тести → 5) performance considerations. Покажи, що думаєш про DX так само як про UX.
«У вас React, ти довго писав Angular — як переходиш?»
Не виправдовуйся. Скажи: "Core concepts — однакові: компонентна архітектура, DI-мислення (custom hooks = services), реактивність. Angular навчив мене думати про архітектуру серйозно. React я вже освіжив — ось що я зробив [конкретно]."
«Як би ти побудував таблицю з мільйоном транзакцій?»
Virtual scrolling (react-virtual / TanStack Virtual). Pagination vs infinite scroll — трейд-офи. Server-side filtering/sorting. Optimistic updates. Skeleton states. Це прямо про їхній продукт — відповідай конкретно.

Твоя позиція: переваги vs ризики

✅ Перевага
Nx monorepo + domain-driven libs — це саме те, що вони хочуть під "DDD, Clean Architecture". Ти вже так думаєш.
⚠ Ризик
React-специфічний синтаксис і паттерни (hooks deps, memo, context) — розімни до співбесіди, щоб не "зависати" на базових питаннях.
✅ Перевага
Досвід з design system і component API design (наприклад, дебати по touch directive, width as input) — це конкретні приклади архітектурного мислення.
⚠ Ризик
Fintech-домен (інвойси, комісії, баланси) — новий. Вивчи базово як працює fee calculation і що таке reconciliation у фінансах.
✅ Перевага
TypeScript — глибокий досвід через Angular. Generic типи, utility types знаєш добре.
✅ Перевага
Вони будують з нуля — це твоя сильна сторона: Nx, архітектурні рішення, масштабованість.
